# 最小诊断 Agent

> 验证状态：尚未完成真实模型、真实实验的端到端验证。当前通过的是模拟模型/执行结果的闭环测试，以及全仓 144 项测试、TypeScript 类型检查和前端生产构建。这些检查不能证明真实模型接入可用或诊断准确。当前默认接入为 Codex CLI，尚未接入 native agent，也未提供运行后端选择。

入口：侧边栏「诊断 Agent」。选择已有实验，点击开始。需要本机安装并登录 Codex CLI（与自然语言生成评分规则共用本机登录）。选择的运行证据会发送给 Codex 使用的模型。

这不是固定顺序的评分工作流：每轮由模型根据当前证据决定下一次工具调用；服务端校验并执行工具，将结果持久化，再调用模型。现有 EvalRunner 继续负责真正的评测任务执行。

```text
目标实验 → 模型决策 → 允许的工具 → E1/E2…证据快照 → 再决策
                          ↓ rerun
                   用户确认 / 已授权预算
                          ↓
                 独立复跑实验（最多1次）
                          ↓
                 新证据 → 修正判断 → 报告
```

## 最小能力边界

- 工具只有列实验、读实验、读运行（含评分依据/轨迹/产物目录）、读文本产物、检查健康、申请复跑和完成报告。
- 默认复跑预算为 0；模型提出具体运行 ID 和理由后等待用户确认。也可启动时授权一次。拒绝后不允许重复申请。
- 硬限制：12 次模型决策，每次 CLI 调用最长 60 秒、最多一次单 case / 单执行器 / 单重复离线复跑，复跑关闭 autoRetry。不是货币或 Token 精确计费预算。
- 线上任务不能通过此入口复跑。只能复跑目标实验中已结束且读取过证据的运行；case 内容 hash 变化时拒绝。当前环境快照保留在新实验中，执行器和服务环境本身仍可能与原运行不同。
- 报告需要引用已有成功证据 ID，且必须先检查目标实验及其运行。模型要判断 Agent 退化，还必须读取另一个实验；是否构成公平可比仍需审阅证据。
- 产物只从运行目录读取，真实路径必须位于配置的 artifactRoot 内。限制文件大小和证据长度，截断会明确标注。
- 不执行模型生成的 shell，不修改评分、不自动修复代码。模型只输出结构化决策，服务端拥有执行权。

## 状态与恢复

状态和证据保存在同一个 SQLite 数据库的 diagnosis_jobs 表。创建复跑实验和扣减预算在嵌套 SAVEPOINT 事务中一起提交，避免检查点缺失后重复创建。

复跑等待最多 3 分钟。超时后保留实验 ID，点击「从检查点继续」只读取已有复跑结果，不创建第二个实验。服务重启后运行中诊断标记为停止，手动继续；底层实验恢复由现有 EvalRunner 负责。

「停止诊断与复跑」会中止模型调用并通过 EvalRunner 尝试取消已创建的复跑。取消是尽力而为，已发生的外部操作不能回滚。原始实验不受影响。

同一服务进程一次只执行一个诊断。最小版本面向单机单实例；多进程部署还需要数据库租约和跨进程锁。

## 验证方式

diagnosis-agent.test.ts 使用可控模型适配器和模拟执行结果，覆盖完整授权闭环、拒绝、预算、恢复、取消、路径边界、非法模型输出、证据引用和事务回滚。它证明 runtime 执行控制正确，不能证明真实模型诊断准确。

真实模型验收：选择一个已知失败实验，确认先读取原始证据；允许一次离线复跑；核对报告中的 E 编号、复跑实验和判断修正。没有充分证据时应输出待验证判断。单次复跑不能证明统计意义上的退化。

接口：GET/POST /api/diagnoses，GET /api/diagnoses/:id，以及 POST /api/diagnoses/:id/approve（approved 布尔值）、resume、stop。变更接口只接受本机来源。
